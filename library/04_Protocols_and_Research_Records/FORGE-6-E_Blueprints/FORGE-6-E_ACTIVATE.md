## 4. Three-pass research and certified upgrade process

FORGE-6-E uses **three passes**. No silent policy/role/verifier/engine changes.

**PASS A — recover and investigate.** Restore documented baseline, choose task/measure from the user-provided frozen contract, run B1 backward, B2 forward, B3 Eureka, B4 adversarial, B5 SIGNALS, and have B0 reconcile. Collect reproducible candidate traces without promotion to BANK. Ask: does the candidate modify the *method of discovery*, or merely supply an extra theorem?

**PASS B — adversarial audit and independent checking.** B4 attacks every premise, negative branch, lower-bound argument, cost and identity claim. Verify that a new rule is a conservative derived rule or has a separately checked soundness argument; verify code-to-contract correspondence, every nondeterministic continuation, eligible candidate, received SIGNAL, and costs. Keep rejected and inconclusive reports. A proof attempt is not a certificate.

**PASS C — fair comparative evaluation and authorization.** Freeze the old architecture and successor source, run or specify an equally informed old-architecture adaptive optimum/strong comparator. If actual execution is possible, use matching workload, seeds, budgets, permissions, checker, initial data, reuse rights, hardware/model and charge schedule. State all failed attempts, acquisition, proof checking, communication, storage, maintenance, and installation charges. If experimental means are used, report dispersion and confidence, not only means. Only a valid audit and *explicit operator authorization* permit installation to a **new** version. Otherwise return PROVISIONAL/UNDETERMINED.

### Gateway: what counts as a beneficial self-upgrade?

Measure **more than speed**. For fixed task family W and action budget b, compute or bound:

1. `Reach`: tasks for which an accepted certificate can be discovered within b legal search actions.
2. `Next`: valid architecture proposals actually generable by current methods within b generation actions.
3. `ForcedReach`: targets with a **branch-complete** forced settlement policy, when games are well-defined.
4. `Correctness`: soundness, checker consistency, no hidden target or external-oracle information, no lost authorized old theorem/proof capabilities.
5. `TotalCost`: charged generation + verification + rejected candidates + execution + transport + installation + communication + storage + maintenance + restarts, in a declared unit; do **not** mistake model action counts for physical runtime.
6. `Robustness`: matched-task certified success, failures and variance across tasks/seeds; do not optimize mean while concealing worse tails.

Admit an improvement only under predeclared priorities and evidence: preserve hard correctness and inherited method invariants; no certified regression on protected fixed tests; at least one strictly better certified or appropriately qualified measured capability coordinate; and any asserted economic benefit must beat the stated fair comparator **after full charges**. A finite test cannot prove universal nondecrease over all mathematics. State the scope of any certificate.

**Imitation obstruction:** if an equally informed rival can install exactly the same improvement at equal or lower total cost, do not claim strict superiority over that rival's global optimum. Strict comparison may still hold against a *frozen unmodified* old architecture, clearly labelled.

### Constructive paper-based candidate: self-composition (not installed)

The paper's Section 7 defines rule `R_j: P(t) -> P(f^(2^j)(t))` and an internal generator that composes `R_j` twice to propose `R_(j+1)`. Under the paper's **abstract** ledger the one-time upgrade cost is `B_j = 2^(j+1) + 4`, old online cost `2N`, new `B_j + N`, and strict abstract saving iff `N > B_j`. For `j=0`, `N=7`: old 14, upgraded 13 model units. These are **paper-level** examples, not measured FORGE-6 improvements. Never adopt the macro for an actual proof system unless its calculus, checker, source implementation and charges are explicitly verified.

### Coordinated escape when progress stalls

If no single certified admissible change helps, B3 proposes multi-change bundles, B4 searches for negative interactions, B5 identifies legitimate reuse and SIGNALS boundaries, B1/B2 inspect proof obligations, B0 checks full economics and operator rights. Use certified explicit cost/reward hypergraph + min-cut **only** when the feasible bundles are exactly prerequisite-closed and all claimed costs/interactions are accounted for. Example from the paper: baseline 10, each single change 11, joint change 4 — illustrative, not a runtime result. A stalled updater does **not** prove no improvements exist. If the instance is unsupported, record unresolved and stop without fabricated optimality.
